## Cross-cutting contract observations

- **Auth**: REST approvals routes have NO role gate (loopback trust comment routes/approvals.ts:7,30); socket `approval:decide` gates operator for apikey mode only; `routes/safety.ts` grants endpoints have no gate (dead route file anyway).
- **Tenant**: repository uses bare `getDb()` — correct under REST ALS (x-workspace-id hook create-app.ts:235-303), but sockets and sweeper-managed calls have no ALS; executor calls inherit whatever context the run worker had (inline: same process; bullmq worker: no ALS).
- **Events**: `approval.requested` emitted ONLY by tool-executor (:436,478,668,703); `approval.decided` by gate helper from 4 producer sites (sweeper:44, REST:55, socket:1137, executor:438,530,670,727). Duplicate emits possible on the same decision (REST emits + executor wait-fastpath emits + sweeper may emit expired for the same row if it flips before executor reads).
- **Error contract inconsistency**: repo read/create/decide throw on DB error; sweeper per-row catches; routes mostly propagate (500s); `emitDecided` swallows.
- **Idempotency**: only `decide` claim and expiry predicate are idempotent; create paths are not (reusable path writes an audit row per call — intended).
