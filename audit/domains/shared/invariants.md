# Shared Domain (non-auth) — Invariants

- INV-1 Tenant scope is server-side only: identity from verified key or loopback mint, never client claims — `sockets/socket-auth.ts:58-72`, `register-socket-server.ts:386-405` (SEC-2 tests).
- INV-2 One tenant mechanism: `runWithDb` ALS is THE request-scope binder; every bare `getDb()` in a request path must resolve tenant — `config/database.ts:20-22`; HTTP `onRequest` binds via callback `done` (`create-app.ts:231-303`); socket/worker paths must bind explicitly (XD-016 class). Worker leg now binds: `run-worker.ts:100-120` wraps execute in `runWithDb(dbForWorkspace(ws))` with unscoped fallback (SH-002 fixed 2026-10-07; regression test TG-4 landed in `queue/run-worker.scope.test.ts`).
- INV-3 Record-only URL resolution: runtime DB URL comes ONLY from the workspace record; env `DATABASE_URL` is CLI-only (migrations/seed/tests) — `config/database.ts:154-171, 320-343`. A hardcoded .env URL must never become a silent database.
- INV-4 Local-first durability: local write is the commit point; PG is a best-effort replica queued to outbox on failure; reads are local-first with PG as gap-filler only — `database.ts:204-279`.
- INV-5 Cache isolation: in-memory caches over tenant data must namespace by `dbScopeKey()` or be scoped out entirely; `"global"` is the only unscoped key — `database.ts:34-44`.
- INV-6 Rooms are workspace-namespaced by ONE scheme (`ws:<id>`, `ws:<id>:channel:<id>`); room scope derives from server truth (channel row), never client claims — `room-keys.ts`, `register-socket-server.ts:569-586` (§30 tests).
- INV-7 Socket execution must be tenant-bound: any inline `runtimeGate.execute` from the socket hub must pass through `executeRunScoped` so artifact/run/message writes inside the runtime resolve the workspace DB — `register-socket-server.ts:327-359` (dispatch `:370`, resume `:1069-1077`; both compliant). The fail-open degrade must be observable: resolver miss/throw emits exactly one structured warn `socket.run.scope_degraded` ({ workspaceId, reason }), try/catch-wrapped so logging can never break the degrade path — SH-005 fixed 2026-10-07, `:330-358`; TG-3 tests in `register-socket-server.test.ts`.
- INV-8 Loopback trust single-source: REST and sockets share `core/loopback.ts` predicate; divergence is a boundary bypass — `loopback.ts`, re-exported by `socket-auth.ts` and auth-gate.
- INV-9 Secrets never persist/log in plaintext: scrypt hashes for pins/keys; AES-GCM envelope for provider credentials; `redact.ts` masks secret-ish keys in logs/reports — `secret-box.ts`, `redact.ts`, `config/env.ts:385-402`.
- INV-10 Serial dispatch: multi-mention is always serial (CrowdOS §10); `MAX_PARALLEL_AGENTS` ignored — `register-socket-server.ts:54-74`, test-pinned.
- INV-11 Config fail-fast: unknown project-prefixed env vars block boot under `CONFIG_STRICT=true` (default); deprecated vars kept parseable but inert — `config/env.ts:310-357`.
- INV-12 Resume parity: resume must ride the same execution path (and therefore the same tenant binding) as live dispatch; a second executor entry point that skips the scope is a defect, not a shortcut — `register-socket-server.ts:1049-1061` (fixed SH-001).
- ALS propagation across fire-and-forget (`void`) executor calls is verified (TG-2, 2026-10-07 s1s2-sweep-1): a `runWithDb` scope whose caller does not await keeps the bound handle for awaits that continue after the caller returns, and does not leak to sibling unscoped work — `config/database.test.ts`.
