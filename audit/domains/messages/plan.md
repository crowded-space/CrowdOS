# Messages Domain - Phase 7 Proposal: Ordered Implementation Plan (no implementation this turn)

Status: proposal only. All items are read-only findings from audit/domains/messages/*. Next turn implements steps in order; each step is small, reviewable, and independently verifiable.

## Rewrite decision

Recommendation: INCREMENTAL REFACTOR (option 2), not rewrite (option 3) and not freeze (option 1).

- Evidence for keeping the core: single write funnel + keyset pagination + local-first commit point are structurally sound and pinned by cross-domain tests and client contract tests; typecheck and gate checks pass; no data-corrupting defect exists in the happy path.
- Evidence against a rewrite: the highest-severity findings (MSG-001/002/007/010/020) are localization/policy fixes in existing seams (unique index, workspace-handle threading, route auth check, outbox replay), not architectural dead ends. A rewrite would risk the client-pinned envelope and the local-first semantics for no structural gain.
- Scope of the refactor: fix silent-loss and isolation defects first, then contract typing, then telemetry/perf. Keep the public gate contract stable; additive changes only (new exports like MAX_PAGE_LIMIT, optional opts), no breaking signature changes.

## Compatibility and risk notes

- Steps 1-4 are correctness/security fixes with additive DB changes (new index, no column changes). Each ships with its own migration and is independently revertible.
- Step 8 return-shape change is the only potentially breaking item; prefer widening types over changing the returned authorLevel value. If the value must change, update the client contract test expectations in the same task.
- Step 9 changes display ids; verify client keying (MainChatArea folds tools by index today, so risk is low) and update the client tests if they pin ids.
- No step creates a branch; all work lands on main per AGENTS.md. Each step: checks -> stop -> user review -> commit only on explicit yes.

1. Focused tests added and passing (npx vitest run <paths>). 2. npm run typecheck green. 3. npm run lint:gates green. 4. Docs updated in the same task when behavior or gate shape changes. 5. Ledger row updated with Status=Fixed plus evidence. 6. User review/test before commit.
