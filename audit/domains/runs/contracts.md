## Cross-cutting contract notes

1. **Emission ownership**: `applyTransition` never emits. Emission happens at three call layers — state-gate (executor walks), resumeRun (service), orphan-sweep. Any new caller of `transition` silently gets persistence without events unless it emits itself.
2. **errorCode clobbering**: every changed transition writes `errorCode: options.errorCode ?? null` (`runs-repository.ts:125`). A recovery hop like `retrying → running` with no errorCode erases the stored failure code. (RUN-001)
3. **Same-state no-op asymmetry**: `transition` returns `changed:false` and does NOT write (no updatedAt touch, no errorCode change). Callers treating "null = failure" must also treat changed=false as success (executor does; `resumeRun` treats changed=false as null).
4. **workspaceId threading is dead**: all 18 ports that accept workspaceId receive undefined from every production caller (grep-verified). Reads/writes both land on ALS getDb() in HTTP scope, shared pool in socket/worker scope.
5. **No txn boundaries anywhere in the domain**: each op is one or more independent statements; the only atomicity is single-statement SQL (checkpoint merge, CAS update) and UNIQUE-constraint retry (compensation seq).
6. **Return-based errors**: no port throws for business rejection. Throws can escape only from the DB layer on connection errors during applyTransition (no try/catch around select/update) — callers that don't catch (e.g. state-gate's callers) will surface a throw.

## Compatibility notes (must preserve)

- Stored formats: `runs.status` enum values (16), `checkpoint` JSONB shape `{watermarkSeq, completedCallIds, historyRef?, updatedAt}`, `inverseOp` JSONB shape incl. the service-read extra `truncated?` flag, compensation `seq` ordering, uuid run ids / text comp ids.
- Event schemas: `run.status_changed` payload keys (runId, agentId, channelId, workspaceId, runtimeType, status, from, reason, errorCode), `run.compensations` entries shape (id, seq, toolName, targetPath, inverseOp {op,path,...}, createdAt ISO).
- Error semantics: null/false/[] unions; `{ ok: false, error }` for undo; HTTP codes above; socket error codes `not_resumable` / `undo_failed` / `forbidden`.
- Queue payload: `resumeContext`/resumeFrom ride untyped (queue comment "checkpoint shape owned by runs"); worker precedence resumeContext ?? resumeFrom.
