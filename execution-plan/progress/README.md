# Progress Tracking

Markdown is the best fit for this tracker.

Why:
- Easy to scan during development.
- Easy to update manually.
- Better for checklists and short change notes than JSON.
- Works well next to the execution plan files.

How to use:
1. Use `00-master-checklist.md` as the main dashboard.
2. Update one feature tracker file when work starts or finishes.
3. Keep change notes short: one line per meaningful change.
4. Mark a task done only after code, test, and manual check are complete.

Status labels:
- `not-started`
- `in-progress`
- `blocked`
- `done`
