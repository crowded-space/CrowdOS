# P0 Chat Core

> Type: Spec — Status: draft — Updated: 2026-10-21

## Purpose

Turn the channel transcript from a "renders whatever the store holds" surface into an honest, anchored, bounded one. Every item here closes a gap between CrowdOS's own locked contract and the code as built, using the Discord corpus only where Discord actually supplies a mechanism.

Eight gaps, in the order they bite:

1. Returning to a channel loses the reading position (RE-P0-01).
2. There is no honest unread anchor, so the unread divider stays dead code (RE-P0-02).
3. Prepend correction uses a raw height delta that breaks on variable-height rows (RE-P0-03).
4. A populated channel flashes the empty onboarding hero while the first page loads (RE-P0-04).
5. A failed history fetch is swallowed into `console.warn` with no retry (RE-P0-05).
6. The locked virtualization budget is unmet (RE-P0-06).
7. The root chat component subscribes to the whole store (RE-P0-07).
8. Orphan tool rows fabricate their timestamp and their id (RE-P0-08).

## How to read this spec

**Item shape.** Every item is a table with ten rows: `Area`, `CrowdOS current`, `Discord reference`, `Target (additive)`, `Steps`, `Acceptance criteria`, `Test`, `Priority`, `Depends on`, `Invariants`. `CrowdOS current` cites real `file:line` in this repo; `Discord reference` cites a `RE/Discord Findings/<Doc>.md` file and the specific mechanism it describes, or says plainly that Discord offers no reference.

**Priority scheme.**

- **P0** = correctness, or a locked-budget blocker. These are items where the code contradicts a locked CrowdOS rule or a `UX_GUIDELINE.md` §12 budget.
- **P1** = high-fidelity interaction parity.
- **P2** = rich features.
- **P3** = polish and rare paths.

This document is P0 only. P1 items live in `P1 Navigation and Panels.md`.

**Every item is ADDITIVE.** No item removes, renames, re-skins, or reorders a CrowdOS surface, slot, view, enum member, or behaviour. Each `Target (additive)` row names explicitly what is preserved. Where a Discord pattern conflicts with a locked CrowdOS rule, the item is re-shaped to fit CrowdOS, and the conflict is recorded in `## Risks and blockers` — never silently applied.

**Acceptance criteria are objectively testable.** Each one can be checked by running a command and reading a number, a DOM query, or a boolean. "Returns the previous scroll offset within ±2px", not "scrolls nicely".

**Testing surface constraint (read this before writing a test).** The client vitest environment is `node` (`packages/client/vitest.config.ts:6`) and the client has no `jsdom` and no `@testing-library/react` (`packages/client/package.json:15-26`). Component *rendering* is therefore not unit-testable today. Every item below therefore separates a **pure logic module** (tested in the `node` vitest environment) from the component wiring, and adds a Playwright spec under `e2e/` where a real DOM assertion is the only honest way to check the behaviour. Adding a DOM test environment is **not** approved — it is in `## Risks and blockers`.

**Definition of Done** for an item = the repo's `AGENTS.md` §2:

- run the repo's own scripts only (`npm run typecheck`, `npm run lint`, `npm test`; `npm run test:e2e` for the Playwright specs) — never raw `tsc` / `vitest` / `eslint`;
- a test that goes through the public surface (the component's public props/store contract for the client; the socket/REST surface for transport code) — never another domain's internals;
- a code change ⇒ a docs update **in the same task** (`AGENTS.md` §6): `re-docs/Frontend Docs/Domain Spec/Chat Area.md`, `re-docs/Frontend Docs/Domain Spec/Stores.md`, `re-docs/Frontend Docs/Feature and Flow Spec/Message rendering.md`, and `UX_GUIDELINE.md` where the change makes the guideline true or false;
- an `AGENTS.md` §9 report at the end of the task, then an explicit `commit?` question. No commit without an explicit yes.

## Scope

**In scope** — `packages/client/components/workspace/MainChatArea.tsx` and `packages/client/components/workspace/messages/*`, the chat-facing slices of `packages/client/stores/crowdOsStore.ts`, and the `e2e/` specs that assert the DOM behaviour.

**Out of scope** — the shell layout, the right operations column, the nav tree and the workspace rail (those are `P1 Navigation and Panels.md`); the composer, mentions and the runtime contract; the backend, the DB schema and the socket protocol. No item in this document changes a socket event, a REST route, a `@crowdspace/shared` type, a Drizzle table or migration, an env var, or a feature flag.

**What this document must not become.** It is not a place to add reactions, typing indicators, keyboard navigation over the transcript, per-message threads, or list semantics on the stream. Several of those appear in the corpus as CrowdOS gaps; each is a separate, later item, and the honest-empty state today is the correct state until then.

## Risks and blockers

- **No DOM test environment in the client.** `packages/client/vitest.config.ts:6` sets `environment: 'node'` and the client declares no `jsdom` / `@testing-library/react` (`packages/client/package.json:15-26`). Every item therefore extracts a pure module for unit testing and uses Playwright (`e2e/`) for DOM assertions. A DOM unit-test environment would let most of the acceptance criteria be checked in `npm test` instead of `npm run test:e2e` — **it is a new dependency and is not approved**; it needs a decision. Until then, the Playwright specs are the only DOM surface, and they skip themselves when the dev stack is down (the pattern in `e2e/chat.spec.ts:10-14` and `e2e/perf-pagination.spec.ts:118-123`).
- **Windowing without a library is the largest single risk in this document.** RE-P0-06 specifies a hand-rolled measured window because no dependency is approved. A measured, variable-height, scroll-anchored window is the exact problem Discord solved with a bespoke anchor system (`../Discord Findings/Scroll Model.md`) and that a library solves better. **Approval of a windowing dependency is required before RE-P0-06 is started**, or the hand-rolled path is accepted knowingly with the risk that RE-P0-03's anchor and RE-P0-08's streaming guarantee are the two things that break first.
- **The god store keeps growing.** RE-P0-01, RE-P0-02, RE-P0-04 and RE-P0-05 add four new slices to a store already described as "~3.2k-line" (`re-docs/Frontend Docs/Domain Spec/Stores.md`). Each is a small map or boolean, but the slice count is the real cost, and RE-P0-07's selector groups must be updated every time a slice is added. Consider one combined `channelViewState` slice holding the scroll memory, the last-read anchor and the load/error state rather than four separate ones — this is a design decision to take **before** RE-P0-01, not after.
- **A server-side read anchor is a backend change and is out of scope here.** Discord's anchor is server-authoritative (`POST /channels/{channelId}/messages/{messageId}/ack`, `../Discord Findings/Scroll Model.md`). RE-P0-02's anchor is **device-local**, so it does not follow the operator to another machine and it does not survive a device-local storage clear. A server-owned `last_read_message_id` on the channel row would be the honest long-term answer; it needs a Drizzle migration, a REST route and a `channel_settings`-style server-authoritative row, which is a breaking-change surface (AGENTS.md §5.5) and is **not** in this document. Until that lands, the docs must say "device-local anchor", not "read state".
- **The virtualization budget has two halves and this document only meets one.** `UX_GUIDELINE.md:167` reads "virtualize past 500 channels / 2,000 messages". RE-P0-06 meets the 2 000-message half. The 500-channel half belongs to the nav list (`WorkspaceSidebar.tsx`), which is a Workspace→Category→Channel tree with collapse and a personal favourites overlay — a different design, owned by `P1 Navigation and Panels.md`, and it is **not** silently dropped: it stays an open item against the same locked budget row.
- **The concurrent `e3fe5f5` commit may shift line numbers.** The file:line references in this document were taken against `main` at `e3fe5f5`. Any later commit that edits `MainChatArea.tsx`, `crowdOsStore.ts` or `RightSidebar.tsx` invalidates them. Re-verify every `file:line` at the start of the task, and re-anchor the docs when the reference drifts.
- **`UX_GUIDELINE.md` drift that these items touch.** RE-P0-06 makes the `UX_GUIDELINE.md:167` list-budget row true for the message list — the row must be amended in the same task to say which half is met and which is open, rather than left to imply the whole row is satisfied. RE-P0-03 changes the prepend strategy, so `re-docs/Frontend Docs/Domain Spec/Chat Area.md` flow 2 ("height anchoring on prepend") and `re-docs/Frontend Docs/Feature and Flow Spec/Message rendering.md` must be updated in the same task. RE-P0-02 changes the "unread deliberately omitted" statement in `re-docs/Frontend Docs/Domain Spec/Chat Area.md` — that sentence is now false and must be corrected, with the device-local scope stated.
- **The `renderedMessages` fold/group pass is O(n) per flush today.** `MainChatArea.tsx:701-847` re-runs the whole fold on every streaming flush because `currentMessages` changes identity. RE-P0-07 extracts it but does not make it incremental; the pass still costs O(n) per flush. A streaming run in a 2 000-message channel will remain the worst case until the fold is made incremental, which is **not** in this document.
- **The 200-message local mirror cap interacts with the unread anchor.** `messagePagination.ts:15` evicts older rows by timestamp when the mirror is written. A last-read anchor that points at an evicted row will not resolve, and the separator will (correctly) not render. That is honest, but it means the anchor silently stops being placeable in long channels unless the server-side anchor (above) lands.

## User Decision:

## Target Contract

> Status: Target. A correct implementation of this document satisfies every invariant below. CrowdOS's locked streaming contract (`UX_GUIDELINE.md:78`, `:177`) is a **locked strength — extend, never churn**; the Discord corpus is a comparison, not a replacement.

* **Follow mode is still decided by wheel and touch intent, never by the `scroll` event** (`use-stick-to-bottom.ts:13-17`, `:56-59`). The scroll event also fires for the app's own programmatic pins, so treating it as intent would cancel follow mode on every token flush.
* **While the operator is scrolled up, incoming messages never move the viewport.** They accrue a missed count capped at 99, and the "Jump to present" pill carries that count and resumes with a smooth scroll (`MainChatArea.tsx:477-479`, `:1232-1248`).
* **Automatic pins stay instant; only an explicit user jump scrolls smoothly** (`use-stick-to-bottom.ts:23-27`, `:45-49`).
* **Prepending older history never moves the visible content, never jumps to the bottom, and never increments the missed count** (`MainChatArea.tsx:471-473`). The correction is anchor-row based and exact to ±2 px, and exactly one correction system is active on the stream container.
* **The three transcript load states are distinct and honest:** skeleton while the first page loads, the onboarding hero only for a genuinely empty channel, and an error with a named cause and a Retry when the load fails (`UX_GUIDELINE.md:34`, `:142`). No state is ever blank, faked, or an eternal spinner.
* **A date divider may only be drawn from a real message timestamp, and an unread marker may only be drawn from a real last-read anchor** (`MainChatArea.tsx:68-84`, `:787-795`). The unread separator renders only against a message id that exists in the loaded window; the sidebar's unread **count** stays a count and is never merged into the separator.
* **Tool executions still fold into the parent agent bubble**, forward and backward; an unpaired tool still renders as its own row, with a stable id and a real timestamp (`MainChatArea.tsx:706-729`).
* **Streaming stays at one store write per flush**, completed blocks stay memoized, and only the pending tail re-renders (`crowdOsStore.ts:1092-1103`, `MentionParser.tsx:233-268`).
* **The transcript reaches the locked list budget and the budget is measured, not asserted**: with 10 000 messages loaded, the mounted row count stays bounded and flat (`UX_GUIDELINE.md:167`).
* **The chat root re-renders only for the store slices it actually reads** (`UX_GUIDELINE.md:167`, "token append updates tail only"), and the observable DOM for a given store state is identical before and after the selector split.
* **Scroll position, unread anchor, load state and error state are workspace-scoped**: two workspaces with the same channel id never share an offset, an anchor, or an error (`AGENTS.md` §5.10).
* **Every state this document adds is device-local and says so.** The read anchor, the scroll memory and the load/error state are client state with localStorage mirrors, exactly like the drafts and outbox mirrors — no new socket event, REST route, shared type, DB column, migration, env var or feature flag (AGENTS.md §5.5).
* **Every item is additive.** The six message types, the folded tool calls, the 300 s grouping rule, the run header, the approval cards, the run cards, the diff injection, the jump-to-present pill, the per-channel drafts, the offline outbox and the composer caps are all exactly as they are today.
