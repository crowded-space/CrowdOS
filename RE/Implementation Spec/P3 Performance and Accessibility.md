# P3 Performance and Accessibility

> Type: Spec — Status: draft — Updated: 2026-10-21

## Purpose

CrowdOS's §12 performance budget and §11 accessibility gates are **locked numbers with nothing measuring them**. The Diagnostics tab exists and reports two budget rows from real marks; the rest are honestly reported as "not instrumented". The shell has `nav`/`main`/`aside` but no `banner`/`contentinfo`; the transcript has no live region for streaming, approval arrival or job completion; the keyboard story stops at four chords; the motion rule that "exactly one surface pulses at a time" is written in CSS as prose and enforced nowhere; the status strip renders only two of its seven segments; and the streaming fold pass re-runs over the whole channel on every 32 ms flush.

This spec is the P3 band that turns those into checkable, executable work. Every item is **additive**: it adds a measurement, a focus route, a landmark, a live region, an arbiter, a real source or a memoization boundary — it never removes a surface and never changes a locked number.

The organising idea: **RE-P3-01 is the item that makes every other performance claim checkable**, and **RE-P3-05 is the item that makes the composer status line honest**. The rest are the interaction and accessibility consequences.

### Priority scheme

| Band | Meaning |
|---|---|
| **P0** | Correctness, or a blocker on a locked budget. Ships before anything else. |
| **P1** | High-fidelity interaction parity with the existing CrowdOS contract — the interactions a user expects every day. |
| **P2** | Rich features. Valuable, additive, and safe to defer without breaking the product. |

P0 and P1 items in the sibling specs are *dependencies*, not competitors: where an item here needs a P0/P1 foundation, the dependency is named in the `Depends on` row and in `## Dependencies and build order`. RE-P3-01 **measures** RE-P0-06's result, and RE-P3-06 **sits on top of** RE-P0-07's extraction rather than redoing it.

### Item IDs

The `RE-P3-nn` ids in this document are **authoritative for the P3 band**: `RE-P3-01`…`RE-P3-07`, and nothing else. `RE/Implementation Spec/Traceability Matrix.md` has been **reconciled** against the five parallel documents: it now cites the real ids, its reverse index covers all **41** of them, and no reserved or placeholder id remains — see `## Risks and blockers` #15. Nothing in the matrix is edited here.

### Additive rule

Every item is additive. Additive means:

- **No existing CrowdOS feature, slot, view, store slice, socket event, ARIA contract or behaviour is removed, renamed or re-skinned.**
- Where an item adds a surface, it adds a *new* surface in the *existing* slot map. A new right-hand surface is a new `rightPanelView` enum value, never a boolean (`UX_GUIDELINE.md:32`).
- Where Discord's mechanism conflicts with a CrowdOS rule, the item **re-shapes** it and says so in `Target (additive)`, and the conflict is listed in `## Risks and blockers`.
- Every `Target (additive)` row names what survives unchanged. A reviewer who cannot name what is preserved has not read the item.
- **No locked number is silently amended.** `UX_GUIDELINE.md:158-171` is load-bearing: a proposal that would breach a budget must either meet it or amend it explicitly, never silently (see `## Risks and blockers`).

### Acceptance criteria

Acceptance criteria are **objectively testable**. Each statement is either true or false when the item lands, checked by the named test or by a manual assertion in the item's `Steps`. "Looks good", "feels right" and "consistent with Discord" are not acceptance criteria and must not appear.

### Definition of Done (per item)

Every item's Definition of Done is AGENTS.md §2, verbatim in force:

1. **Repo scripts only.** Never call the underlying tools directly — use `npm run typecheck`, `npm run lint`, `npm test`, `npm run lint:gates` from the repo root (and the workspace-scoped variants). `npm run check:docs` does **not** exist yet; if a task needs it, the item is blocked on building it.
2. **Test through the public surface.** Client behaviour is tested through the store or a pure model module; server behaviour through the domain gate. Do not reach into another domain's internals. The client test environment is `node` (`packages/client/vitest.config.ts:6`) with no DOM and no Testing Library, so client acceptance is asserted against **pure model modules**, store actions and source-file assertions — never against rendered markup. Adding a DOM test environment is a new dependency and is routed to `## Risks and blockers`.
3. **Code change ⇒ docs update in the same task.** Touching a gate shape updates that domain's `Domain Spec`; touching a flow updates the `Feature and Flow Spec`; a gate-shape change also updates the root `_index.md` if gates move.
4. **§9 report.** The final report uses the exact AGENTS.md §9 shape: `Cause` · `Changed` · `Tests added` · `Checks` · `Blast radius` · `Invariants` · `Docs updated` · `Not done`, then the `commit?` question.

## Target Contract

> Status: Target. CrowdOS's §12 budget and §11 accessibility gates are **locked numbers with nothing measuring them**. This document turns them into measured, asserted and verified behaviour — without changing a single locked number and without removing a single existing surface.

* **The §12 budget numbers are not changed by this document.** RE-P3-01 measures them; where a row cannot be measured it says so; where a row is over budget it says so. The virtualization conflict (`UX_GUIDELINE.md:167` vs no windowing dependency) is reported, not amended.
* **Every budget row ends in an honest three-state verdict** — `within`, `over`, or `not instrumented` — and a row with no measurement never shows a number, and never shows `0`.
* **Diagnostics is where violations surface** (`UX_GUIDELINE.md:171`), and it stays a read-only surface that carries counts and latencies only, never message content, file contents, secrets or memory writes (`UX_GUIDELINE.md:144`).
* **One shortcut registry, one scope model.** Every chord is declared once, with an id, a chord, a scope and a description; the four existing chords keep their exact behaviour; a hidden shortcut that mutates state is forbidden.
* **The transcript gains list semantics and roving tabindex**; the composer popovers use `aria-activedescendant` with DOM focus on the textarea. Both models are already the house patterns (`FileExplorer.tsx:280-318`, `MainChatArea.tsx:510-529`), and neither is introduced twice on the same widget.
* **The landmark set is complete and unique** — `banner` · `navigation` · `main` · `complementary` · `contentinfo` · `status` — with no furniture added and no existing landmark moved or renamed.
* **Live regions are owned, quiet and single.** Streaming announces a completed turn, never a token; approval arrival announces once; job completion is announced by the existing toast channel, exactly once; the transcript is never a live region.
* **Exactly one surface pulses at a time.** The arbitration order is `approval` → `swarm` → `agent-working` → `mention-arrival` → `skeleton`; one-shot animations are exempt; `prefers-reduced-motion` still collapses everything to static; the roster still ticks without pulsing; the approval still pulses until decided.
* **The status line shows only what has a source.** Every rendered segment opens its source view; a segment with no source hides rather than showing `0`; the context-% segment stays hidden until the Context domain publishes a channel-scoped meter; the strip stays props-only and stays one line, never modal.
* **A streaming flush touches only the streaming tail.** The settled fold-and-group projection keeps a stable identity across a flush; the fold rule, the grouping rule, the orphan-tool behaviour and the one-write-per-flush coalescer are unchanged; the whole-store subscription is left as a recorded gap, not silently rewritten.
* **Contrast is verified by a sampler, not asserted in prose.** The sampler reads the real stylesheets, checks both themes against their thresholds, and fails loudly; it never changes a colour to make itself green. Focus rings become design tokens without changing what they look like or bringing back a global outline.
* **Nothing existing is removed, renamed or re-skinned**, and every code change updates its owning docs in the same task, with the AGENTS.md §2 definition of done and the AGENTS.md §9 report.
