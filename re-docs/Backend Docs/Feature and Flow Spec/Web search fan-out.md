# Web search fan-out
> Type: Feature · Status: aligned · Updated: 2026-09-26

## Intent
Research needs web evidence even when providers are down, unconfigured, or disagree — and the same URL surfacing from three backends must count once. This feature exists so one query fans out to Brave, Tavily, and Serper, per-provider failures degrade to fewer sources instead of an error, and the merged union dedupes by normalized URL before anything downstream sees it. The `web_search` tool consumes the same gate.

## Architectural decision
Recall over cost and latency: every configured backend is always queried and results merge as a union, never failover — priority order affects output ordering, not backend selection `[Observed]`. Each provider fails open (warn-once + `[]` on missing key; warn + counted throw on HTTP error, 429, parse failure, or abort) with one aggregated no-key warning and one loud `ALL N attempted providers failed` warning when every fetch threw, so search degrades to fewer sources, never to a thrown error `[Observed]`. Dedupe is first-seen-wins on aggressive URL normalization (case, `www.`, default ports, slashes, tracking params, fragments, http/https unified), so provider priority decides which copy survives `[Observed]`. Limits are enforced twice — per-backend clamp plus a final gate slice — so one greedy backend cannot starve the union's diversity `[Observed]`. Fan-out is hybrid: the first provider is awaited sequentially with the full limit (so the early-exit can fire), the rest run in parallel via `Promise.allSettled` — worst-case gate latency ≈ 5s + 5s ≈ 10s, bounded against Research's 6s caller timeout through the composed abort signal `[Observed]`.

## How it works
Non-string and blank queries short-circuit to `[]` with zero provider calls; queries are truncated to 512 chars; `limit ≤ 0` returns `[]`, non-finite limits fall back to default behavior. Otherwise `SEARCH_PROVIDER_PRIORITY` (comma-split, lowercased, blanks dropped) sets the order, defaulting to brave → tavily → serper; unknown names warn once listing the valid options, and any default provider missing from a custom list is appended, so all three always run. Provider #1 is awaited first with the full `limit` (early-exits when its deduped results already reach the limit); the remaining providers run in parallel, each with `ceil(limit/n)`, via `Promise.allSettled` with rejects warned-and-skipped by provider name plus truncated query. Each provider has its own limit (clamped 1–20, default 10), timeout (5s default composed with the caller signal, so user cancel actually cancels in-flight search), and abort handling. Per-backend mapping: Brave reads `BRAVE_API_KEY` and GETs the web-search endpoint with `X-Subscription-Token`; Tavily reads `TAVILY_API_KEY` and POSTs `max_results` with basic depth; Serper reads `SERPER_API_KEY` and POSTs `q`/`num` with `X-API-KEY`. Each maps its own result envelope to `{ url, title, snippet, timestamp?, source }` with title/snippet truncation at the mapper boundary; unparsable timestamps are warned once per mapper call and dropped, so they carry no freshness signal instead of sorting as oldest. Non-OK HTTP (incl. 429 with `Retry-After` when present) and HTTP-200-unparseable-JSON warn and throw so the service counts the failure. When the union is empty and no key is set anywhere, one `No search provider configured` warning fires; when every attempted provider threw, one `ALL N attempted providers failed` warning fires. `dedupeByUrl` normalizes each URL (lowercased host, `www.` strip, default-port and fragment drop, trailing-slash drop, tracking-param strip, param sort, http → https canonicalization; trim/lowercase fallback for unparseable input), keeps the first occurrence, and reports later ones as `{ url, duplicateOf }`. A final `opts.limit` slice caps the deduped union. Research consumes this per sub-question (`limit: 8`, 6s timeout, `research-runtime.ts:423`) and applies its own second layer — `dedupeEvidence` plus `sortByFreshness` re-exported from this domain (`research-runtime.ts:484-485`) — before synthesis. The `web_search` tool calls `searchProviderGate.search(query, { limit: 8 })` (`tool-registry.ts:518-521`).

## Current state
Real: priority ordering with append-not-drop and unknown-name warn, hybrid first-sequential/parallel fail-open fan-out with full-limit early-exit, all three backend mappers with key guards and truncation, aggressive normalization (incl. http/https unification) with first-seen-wins dedupe, dual limit enforcement, 429/JSON-parse warns that throw (counted), aggregate all-failed warn, and caller-signal composition. No DB, no broker, no persistence — stateless per call, diagnostics via `console.warn` only. Similarity/freshness dedupe live in this domain as gate ports (`dedupeEvidence`, `sortByFreshness`); `research-runtime.ts:7` re-exports them for compat. Known rough edges that are real: callers still receive `[]` for both total failure and genuine empty (distinguishable only via the aggregate warn in logs), and 429s are not retried.

## Open gaps
- Total failure vs genuine empty is indistinguishable to callers (return type stays `[]`); only the aggregate `console.warn` distinguishes them in logs. Closing needs a coordinated caller-contract change across Runtime and Tools.
- `source` is a free-form mapper-stamped string with no union type — a mapper typo flows into artifacts unchecked.
- No 429 retry/backoff: rate-limited providers count as failed for the call; add backoff if throttling is observed.
- `__testMap*Json` mapper entry points are domain-internal test hooks, not gate ports — deliberate (in-domain tests only).
