# Explorer ops flow
> Type: Flow · Status: aligned · Updated: 2026-10-04
## Intent
Browse the effective root for the active channel, mount or clear the working directory it points at, open a file into the chat editor, and review run diffs with minimal surprise.
## Architectural decision
- [Observed] One root request carries both the scope and the listing, so the panel header and the tree can never disagree about which directory is on screen (`FileExplorer.tsx:176-197`; `routes/filesystem.ts:91-125`). The earlier design fetched them separately and could.
- [Observed] Folders fetch children lazily and cache per path; later toggles reuse the cache and Refresh is the explicit re-read (`FileExplorer.tsx:204-238`).
- [Observed] File selection is a store-state handoff (`selectedSandboxFile`), not a prop chain, so the tree and the chat popup stay decoupled (`FileExplorer.tsx:552`).
- [Observed] Mounting writes to the server first and then bumps `filesystemRevision`, never an optimistic local copy: the server owns the mount, so the panel, the tools, and every other reader re-resolve from one authority (`FileExplorer.tsx:378-411`).
- [Observed] Zone A (Workspace Local) is a separate labelled root inside the same panel, openable read-only there, and rendered only when the roster contains an L0 agent (`FileExplorer.tsx:559-607`). File activation carries the `workspace-local` root (`selectedSandboxRoot`), so the viewer reads the same directory the tree listed.
- [Observed] Diff apply/revert/apply-all/restore share one store busy lock (`diffBusy`) with error-with-cause-and-retry (`diffError`) — only one mutation at a time; per-file Copy/Download, real-payload hunk notes (honest empty when absent), and a pre-apply `getWorkspaceFileContent` conflict notice with Apply-anyway/Dismiss (`DiffViewer.tsx`).
- [Observed] Checkpoint + restore: `CheckpointRow { runId; runtime }` above the inline diff for Coding/Swarm runs (gate via `runRuntimeByRun` from real `run.status_changed` payloads); snapshot is min `createdAt`, files are distinct paths; Restore previews the file list in a `ConfirmDialog` and calls store `restoreRun`, which sequences the existing revert transport and records `restoreAuditByRun[runId]` rendered back by the row.
- [Observed] Scope-preview confirms: Clear mount names the current path + resulting inheritance change; Clear history carries a retention notice (not retained, cannot be undone); Restore lists files; Leave is unchanged (already scoped).
- [Observed] Mounts matrix (2026-10-04): the Settings Mounts tab renders Workspace, Category, and Channel cards side by side with the effective winner badged and why-explained, each card browsing through the same `FolderMountPicker` used by the panel header; Clear stays confirm-guarded and only-while-set; override replaces, never merges.
- [Observed] Bottom drawer tabs (`BottomDrawer`, `bottomDrawerView: file | diff | log`) below the center chat: file tab is preview-vs-pinned per-workspace, diff tab reuses `DiffViewer` for the latest run, log tab is read-only channel state (`src/App.tsx` named slot).
## How it works
1. Browse: the panel drives two `useDirectoryTree` instances — `effective` always, `workspace-local` only when `hasL0Agent(agents)`. Each fetches `GET /api/workspace/files?path=/&workspaceId=…&channelId=…&root=…` on mount, on workspace/channel change, and on every `filesystemRevision` bump; the route resolves the root through `channelMountGate.scope` and answers `{ …scope, root, nodes }`, or 404 when the resolved root is gone (`FileExplorer.tsx:176-202`). States render in order: loading → failure → empty → tree (`:534-557`).
2. Mount: `OPEN FOLDER` calls `pickDirectoryNative(repo.scope?.path)` when the desktop bridge is present, then `PUT /api/channels/:id/mount` with the picked path, then `incrementFilesystemRevision()` plus a success toast (`FileExplorer.tsx:391-411`). Without a bridge the same button toggles the in-app `FolderMountPicker` instead — a browser tab cannot open a native dialog, and `POST /api/fs/pick-folder` is a hard 410 (`FolderMountPicker.tsx:100-104`). Cancel and empty selections return silently; a rejected path surfaces the route’s message through `showError`.
3. Clear: the `Clear` button (shown only while mounted) PUTs `{ folderPath: null }` and the channel falls back to its category/workspace inheritance (`FileExplorer.tsx:494-510`). The Settings Mounts tab offers the same Clear per Workspace/Category/Channel card, confirm-guarded, only while a path is set (`MountsInspector.tsx:309-320,496-511`).
4. Open: clicking a file sets `selectedSandboxFile` plus its root (`effective` for the repository, `workspace-local` for Zone A) in the store; the chat code popup renders `SandboxCodeViewer` for that path with that root, scoped to the same workspace **and channel** so it resolves the same root, with syntax coloring applied by `workspace/code-highlight.ts`. Zone A files open read-only with an `L0` badge and a no-save guard (Save/Revert disabled, editing locked).
5. Edit: file content save goes over REST via `apiClient` (`.getWorkspaceFileContent` / `.saveWorkspaceFileContent`), not sockets; a failed load renders an error panel rather than a fake `// File not found` comment (`SandboxCodeViewer.tsx:15-67`). Sandbox updates then bump `filesystemRevision` via `sandbox:updated` and re-fetch every root (`crowdOsStore.ts:1322-1331`).
6. Diff: `DiffViewer` fetches artifacts per `runId`, classifies patch lines (`parsePatchLines`), splits hunks (`splitHunks`) for the real-payload `HunkNotes` slot, and toggles unified vs side-by-side views (`DiffViewer.tsx`).
7. Apply: per-file Apply first reads the live file (`getWorkspaceFileContent`) and blocks on conflict (amber notice, Apply-anyway/Dismiss), then writes `contentRef` via `apiClient.applyFileContent` and bumps `filesystemRevision`; failures land in `diffError` with Retry; Apply-all sequences this per file for the run.
8. Revert: per-file Revert reconstructs the before-image from the patch (or deletes when no `beforeHash`) and bumps `filesystemRevision`; failures land in `diffError` with Retry.
9. Checkpoint + restore: `CheckpointRow` above the inline diff for the latest Coding/Swarm run (gate via `runRuntimeByRun`); snapshot is min `createdAt`, files are distinct paths; Restore confirms with the file list and calls `restoreRun`, which sequences the existing revert transport and records `restoreAuditByRun[runId]` rendered back by the row.
10. Drawer tabs: the file tab shows pinned-else-preview with a per-workspace toggle, the diff tab reuses `DiffViewer` for the latest run, the log tab reads the channel list read-only — all under the `div[data-slot="bottom-drawer"]` named slot below the center chat.

## Target Contract
> Status: Target. Flow-scoped view. Authority stays in linked area and domain docs.
* The panel root and the agent tool root MUST be the same path for the same `(workspaceId, channelId)`. A panel that lists a different directory than the agents work in is forbidden.
* Lazy folder fetch with a per-path cache stays, bounded by manual plus filesystemRevision-triggered refresh.
* File selection stays a store-state handoff via `selectedSandboxFile`, never a prop chain.
* Mounting MUST write through the server and re-resolve from the revision bump, never from an optimistic local copy.
* `OPEN FOLDER` MUST be reachable from the panel, and MUST degrade to the in-app navigator where no desktop bridge exists. An unreachable picker or a call to the 410 route is forbidden.
* Diff apply, revert, apply-all, and restore share one store busy lock (`diffBusy`) with error-with-cause-and-retry (`diffError`). Concurrent mutations on one artifact are forbidden.
* Checkpoint restore previews its file scope and records a `restoreAuditByRun` entry rendered back by the row. Scope-blind restore is forbidden.
* Destructive confirms preview scope: clear-mount names the resulting inheritance, clear-history states the retention loss, restore lists files. Scope-blind destructive action is forbidden.
* The bottom drawer keeps named `file | diff | log` tabs under a stable slot below the chat. Boolean-addressed drawer views are forbidden.
* Edit popup defines save affordance, dirty tracking, and conflict handling. Handoff-only tracing is forbidden.
* Diff apply surfaces failures, defines conflict and 3-way behavior, and documents post-apply refresh.
* Tree cache invalidates on `filesystemRevision` plus move and rename, not root re-fetch only. Authority: Filesystem Explorer area doc; Filesystem, Artifacts standards.
## Open gaps
- Edit-popup details (save affordance, dirty tracking, conflict handling) live in Chat Area; this flow traces only to the handoff point. The fake content fallbacks were removed, so a load failure is now visible — but the popup still has no conflict handling.
- Diff conflict/3-way notes: the pre-apply guard now surfaces live-vs-snapshot conflicts with Apply-anyway/Dismiss and failures land in `diffError` with Retry; true 3-way merge stays out of scope — no merge UI is implied.
- Tree children cache never invalidates except on root re-fetch or a revision bump; a mid-session move/rename can still desync expanded nodes.
- Zone A preview-after-reload: `BottomDrawer` persists preview/pinned paths to localStorage without the root, so a stale Zone A preview after reload can resolve through the wrong root — documented gap, deliberately out of scope for this patch (per user decision).
- The L0 gate for Zone A uses the agent roster as a proxy for operator identity, so an empty roster hides the zone even for an L0 operator.
